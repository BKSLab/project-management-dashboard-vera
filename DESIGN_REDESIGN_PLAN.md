# План смены дизайна дашборда — Dark Developer Workspace

> Статус: редизайн реализован и визуально проверен; выявленные проблемы адаптивности исправлены. Источник требований — ТЗ пользователя «Концепция дизайна интерактивного дашборда проекта» (получено в ходе обсуждения, не оформлено отдельным файлом — зафиксировано здесь).
>
> Исходный дизайн был тёмной темой с золотым акцентом (`#0A0A0A` / `#F5B800`), перенесённой из `site_work_for_everyone`. План перехода на стиль «VS Code + Postman + Linear» выполнен; актуальные токены находятся в `frontend/src/app.css` и `docs/DESIGN_GUIDE.md`.

---

## 1. Цели и границы

**Цель:** дашборд должен ощущаться как рабочая среда разработчика (VS Code/Postman/Linear), а не как корпоративный сайт — выше плотность информации, спокойные многоуровневые тёмные поверхности, синий/бирюзовый акцент вместо золота, осторожный glass только на крупных контейнерах (sidebar/header/панель деталей/модалки), без него — на канбан-карточках и списках.

**Что входит в этот план:**
- Полная замена цветовых токенов, теней, типографики (`app.css`).
- Редизайн всех UI-примитивов (`Button`, `Badge`) и layout (`Header`, `Footer`).
- Редизайн канбана (`Column`, `TaskCard`, `Board`/drag&drop) под спецификацию из ТЗ.
- Перенос деталей задачи из правой панели в центральный `TaskModal` в стиле Postman/Linear.
- Редизайн дерева ИСР (`WbsNode`) под новые токены (без смены структуры/логики).
- Обновление `docs/DESIGN_GUIDE.md` как актуального источника истины по стилю.

**Решения по открытым вопросам (зафиксированы, см. бывший раздел 7):**
- **Приоритет задачи (`LOW/MEDIUM/HIGH/CRITICAL`) — не делаем.** В проекте нет понятия приоритетных задач, поле в `KanbanTask` не добавляется. Плашка приоритета из ТЗ исключается из макета карточки полностью.
- **Счётчик + превью последнего комментария на карточке — делаем, в этой же итерации.** Требует backend-изменений (раздел 7) наравне с фронтендом — не откладывается на отдельный проход.
- **Активный пункт навигации в Header — не подсвечивается.** Принцип `DESIGN_GUIDE.md` («только `aria-current`, без цвета») сохраняется, несмотря на Linear-стиль остального ТЗ.

## 2. Дизайн-токены (`frontend/src/app.css`)

Полная замена блока `:root` / `@theme inline`. Без хардкода `#000000` фона (только `#111827`).

```css
:root {
  /* поверхности, 4 уровня */
  --background: #111827;      /* было #0A0A0A */
  --surface: #1a1f2e;          /* было #1A1A1A */
  --surface-elevated: #242b3d; /* новый уровень — карточки/панели */
  --surface-hover: #2f374d;    /* было #252525 */
  --surface-active: #374151;   /* новый — активный/выбранный элемент */

  --border: rgba(255,255,255,0.05);       /* было #2D2D2D */
  --border-hover: rgba(255,255,255,0.12);

  --foreground: #F0F0F0;       /* без изменений */
  --muted: #9CA3AF;             /* было #999999, более холодный серый */

  /* акценты — сине-фиолетовый вместо золота */
  --accent: #6366F1;           /* было #F5B800 */
  --accent-hover: #7C83FF;
  --accent-foreground: #FFFFFF; /* было #0A0A0A — текст на акценте теперь светлый, не чёрный */

  --accent-secondary: #06B6D4;  /* бирюзовый — успех/активность/связи */
  --warning: #F59E0B;
  --danger: #EF4444;
  --success: #10B981;
}
```

Дополнительно (вне `@theme`, как утилитарные CSS-переменные/классы — `box-shadow` нельзя завести через Tailwind `@theme inline` цветовым токеном):

```css
--shadow-panel: 0 4px 20px rgba(0,0,0,0.3);
--shadow-card: 0 2px 8px rgba(0,0,0,0.25);
--shadow-card-hover: 0 8px 25px rgba(0,0,0,0.35);
--shadow-selected: 0 0 0 1px rgba(99,102,241,0.7), 0 8px 30px rgba(99,102,241,0.15);
--shadow-dragging: 0 15px 40px rgba(0,0,0,0.45);
```

`@theme inline` дополняется маппингом `--color-surface-elevated`, `--color-surface-active`, `--color-border-hover`, `--color-accent-secondary`, `--color-warning`, `--color-danger`, `--color-success`, чтобы их можно было использовать как Tailwind-классы (`bg-surface-elevated`, `text-accent-secondary` и т.д.) — тот же паттерн, что уже есть для `--color-accent`.

**Что не трогаем:** keyframes `braille-dot` (лоадер на главной) — пересчитать цвета внутри под новый `--accent`, но не удалять.

## 3. Типографика

- Основной шрифт: **Inter** (приоритет) или **IBM Plex Sans** — подключить через `<link>` на Google Fonts в `index.html` (в Vite SPA нет `next/font`, как и сейчас с Geist).
- Моноширинный: **JetBrains Mono** — для `TASK-{id}`, кодов ИСР (`wbs_code`), дат, статусных меток. Подключить тем же способом.
- Заменить текущий Geist (упомянут в `DESIGN_GUIDE.md` раздел «Типографика») — Geist был решением для копии дизайна `site_work_for_everyone`, для нового стиля не подходит.
- `font-family` для `font-mono` Tailwind-утилиты переопределить через `@theme inline { --font-mono: "JetBrains Mono", monospace; }`.

## 4. UI-примитивы

### 4.1. `Button.tsx`
- `primary`: `bg-accent text-accent-foreground hover:bg-accent-hover` (было золото/чёрный текст → сине-фиолетовый/белый текст).
- `secondary`: рамка `border-white/10` вместо `border-accent/50`, фон `bg-white/5`, текст `text-foreground` (не `text-accent` — в новой концепции акцент используется точечно, не на всех secondary-кнопках, как было в DESIGN_GUIDE).
- Добавить мягкий `transition` (150–200ms) на все варианты — Material-принцип «плавные переходы», сейчас transition нет вообще ни на одном варианте.
- `focus-visible:outline-accent` — сохраняем, это требование доступности (раздел WCAG в `DESIGN_GUIDE.md` не отменяется новым визуальным стилем).

### 4.2. `Badge.tsx`
- Базовый цвет фона `bg-surface-elevated` вместо `bg-border` (`bg-border` после смены токенов стал почти прозрачным — `rgba(255,255,255,0.05)` — не годится как фон бейджа).
- Вариант `priority` не добавляется — поле приоритета в проект не вводится (решено).

## 6. Канбан — основной объём работы

### 6.1. `Column.tsx`
- Фон колонки: `#1a1f2e` (`bg-surface`), `rounded-2xl` (16px, сейчас `rounded-lg` = 8px), внутренний паддинг 16px (сейчас `p-2` на скролл-контейнере — мало).
- Заголовок колонки: `IN PROGRESS · 12 задач` — `uppercase tracking-[0.1em] font-semibold`, сейчас обычный `font-semibold` без uppercase/tracking.
- Подсветка колонки-получателя при drag-over: `bg-accent/[0.08] border border-accent/30` — сейчас `bg-accent/5` (близко, но без рамки) — дополнить рамкой.

### 6.2. `TaskCard.tsx` — переписывается полностью под структуру из ТЗ

Целевая структура карточки (адаптация ТЗ — без плашки приоритета, поле не вводится):

```
TASK-145
Настроить API обработки заявок
Краткое описание задачи в две строки...
💬 Добавлена обработка ошибок...
Backend/API          04.08          💬 3
```

Конкретика по стилям:
- `TASK-{id}` — `font-mono text-xs text-muted` (заменяет текущий `wbs_code`-бейдж как идентификатор; `wbs_code` показываем отдельно в нижней строке, как сейчас).
- Заголовок — `line-clamp-2`, `text-[15px] font-semibold` (сейчас `font-medium`, без ограничения строк).
- Описание (если есть, иначе блок не рендерится) — `line-clamp-2 text-[13px] text-muted leading-[1.4]`. Сейчас описание на карточке вообще не показывается — добавить.
- Последний комментарий (если есть, иначе блок не рендерится) — `💬 {текст}`, `line-clamp-1`, фон `bg-white/[0.03]`, `rounded-lg` (8px) — данные из нового backend-агрегата (раздел 7).
- Нижняя строка: `wbs_code` (моно, `text-accent-secondary`, не текущий `text-accent/80`) + дата (цвет по правилу просрочки: `danger` / `warning` / `muted`, текущая логика `isOverdue` остаётся, добавляется промежуточное состояние «скоро» — порог ≤3 дня) + счётчик комментариев `💬 N` (из того же backend-агрегата).
- Hover: `translateY(-2px)` + `shadow-card-hover` + `border-white/10`, переход `0.2s ease`. Сейчас hover вообще не меняет позицию карточки, только тень/рамку под золото.
- Highlighted (переход из ИСР, `?highlight=`) — заменить золотую рамку/свечение на `shadow-selected` (рамка `accent` 1px + свечение `rgba(99,102,241,0.15)`).

### 6.3. Drag & drop (`Board.tsx` + `@dnd-kit`)
- Во время перетаскивания: `scale(1.03) rotate(1deg)`, `shadow-dragging`. Сейчас активный драг — просто `opacity-40` на исходнике (через `useDraggable`/`isDragging`), визуального стиля «летящей» карточки нет — её рисует `@dnd-kit` через `transform` от `useDraggable`, нужно добавить `DragOverlay` (`@dnd-kit/core`), которого сейчас в `Board.tsx` нет вообще — без него стилизовать «поднятую» карточку поверх остальных колонок невозможно технически.

> Технический нюанс, который обязательно проявится при реализации: текущий `TaskCard` использует `useDraggable` без `DragOverlay`, поэтому перетаскиваемая карточка двигается «на месте» в потоке документа, а не свободно над колонками. Эффекты `scale`/`rotate`/усиленная тень из ТЗ нормально выглядят только в `DragOverlay`. Добавление `DragOverlay` — небольшое, но реальное изменение логики `Board.tsx`, не только CSS.

## 7. Backend-изменение: агрегат комментариев на карточке

Единственное API-изменение в этой итерации (приоритет и подсветка навигации — отклонены, см. раздел 1). Нужно для блока «💬 Последний комментарий» и счётчика `💬 N` на `TaskCard`.

- **`KanbanTasksService.get_task_list`** (`backend/src/services/kanban_tasks.py`) — обогащает задачи контекстом ИСР и агрегатом комментариев, полученным через отдельные репозитории.
- **`TaskSchema`** (`backend/src/schemas/kanban_tasks.py`) — содержит `comments_count: int` и `last_comment: str | None`; полный список комментариев показывается в `TaskModal`.
- Без миграции Alembic — данные считаются на чтении из существующей таблицы `task_comments`, новых колонок не требуется.
- Инвалидация: `addCommentMutation` в `TaskModal.tsx` обновляет и комментарии задачи, и общий список задач, поэтому счётчик на карточке меняется сразу.
- Фронт: `lib/types.ts` → `KanbanTask` дополняется `comments_count: number`, `last_comment: string | null`.
