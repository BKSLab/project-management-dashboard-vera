# Сводка по проекту

Собирает связный текст о состоянии проекта, пригодный для отправки заказчику
или для планёрки.

Достаточно MCP-токена **только на чтение**: скил ничего не меняет.

## Шаги

1. Если проект не назван — вызовите `list_projects` и уточните.
2. Вызовите `get_project`: получите стадии, число задач в каждой и общий статус.
3. Вызовите `list_tasks` без фильтров, чтобы увидеть всю картину, включая
   завершённые задачи.
4. Разложите задачи по группам:
   - завершены (задачи в стадии с `is_done=true`);
   - в работе;
   - просрочены — `due_date` в прошлом и задача не завершена;
   - без срока.
5. Для задач, которые выглядят проблемными (просрочены или давно висят),
   вызовите `list_comments` — там обычно и лежит причина.
6. Если нужны решения и договорённости, а не только статусы, вызовите
   `search_project_knowledge` с вопросом по теме: он ищет по смыслу в задачах,
   документах, комментариях и вложениях.

## Правила

- Числа берите из ответов инструментов, не пересчитывайте на глаз и не
  округляйте «примерно».
- Про каждую просроченную задачу пишите причину, если она есть в комментариях,
  и честно пишите «причина не зафиксирована», если её нет.
- Не превращайте сводку в перечень всех задач. Читателю нужны завершённые,
  проблемные и то, что изменилось, — остальное лишнее.
- Ссылайтесь на задачи их ключами (`PROJ-142`): по ним человек найдёт задачу в
  интерфейсе.
- Не оценивайте работу людей. Констатируйте факты: сроки, статусы, блокеры.

## Формат ответа

```
## Проект <название> — сводка

**Итог.** Одно-два предложения: где проект в целом.

**Завершено:** N задач
- PROJ-140 · Название

**В работе:** N задач
- PROJ-142 · Название · Борис · срок 10.09

**Просрочено:** N задач
- PROJ-138 · Название · срок был 28.08 · причина из комментария

**Требует решения**
- Вопрос, по которому нужен ответ владельца
```

Раздел «Требует решения» опускайте, если таких вопросов нет. Пустые разделы не
пишите вовсе.
