# Примеры скилов для работы с трекером через MCP

Три готовых скила для Claude Code. Возьмите нужный, положите в каталог скилов
своего проекта и правьте под себя — это заготовки, а не финальные инструкции.

Примеры намеренно **сценарные, а не по одному на каждый инструмент**. Список
доступных инструментов Claude Code видит сам из MCP-сервера, и дублировать его
скилами бессмысленно: такой набор устареет при первом изменении контракта.
Ценность здесь в том, как трекер используется в работе.

## Установка

1. Откройте раздел «MCP» в трекере, выпустите токен и скопируйте готовый блок
   конфигурации в конфиг Claude Code.
2. Скопируйте нужный каталог скила в `.claude/skills/` своего проекта.
3. Проверьте: спросите агента «какие у меня проекты» — он должен вызвать
   `list_projects`.

## Что есть

| Скил | Что делает | Нужен токен |
|---|---|---|
| [`triage-inbox`](triage-inbox/SKILL.md) | находит незаполненные задачи и предлагает раскладку | на запись |
| [`weekly-digest`](weekly-digest/SKILL.md) | собирает сводку по проекту за неделю | на чтение |
| [`tasks-from-notes`](tasks-from-notes/SKILL.md) | заводит задачи из заметки встречи | на запись |

`weekly-digest` работает с токеном только на чтение — начните с него, если не
хотите сразу давать агенту право менять данные.

## Общее правило в этих скилах

Каждый скил, который пишет в трекер, обязан **показать план и дождаться
подтверждения** перед вызовом изменяющих инструментов. Агент, самостоятельно
создающий и удаляющий задачи, ошибается молча и дорого.
