# Источники аналитики проекта и портфеля

Оба режима используют один сборщик данных и один формат контекста. Различаются
подробность текстовых фрагментов и задача системного prompt: анализ внутри проекта
либо сравнение активных проектов, доступных пользователю. Портфель сохраняет прежнюю
область — проекты в статусе `ACTIVE`.

| Источник | Передаваемые сведения |
| --- | --- |
| Проект | Код, название, описание, статус, начало и срок завершения |
| Команда | Логин, ФИО и проектная роль; без контактов, паролей и служебных полей |
| Стадии | Название, порядок и признак завершения |
| Задачи | Ключ, название, описание каждой задачи, приоритет, исполнитель, роль, текущие и исходные плановые сроки, фактическое завершение, размещение в ИСР |
| Чек-листы задач | Ключ задачи, название чек-листа, тексты пунктов в исходном порядке, отметки выполнения, полное число пунктов и число выполненных |
| Назначения | Исполнители, постановщики, наблюдатели с реальными ключами задач |
| Комментарии | Текст, автор, время и задача |
| Вложения | Имя файла, MIME-тип, размер, время загрузки и задача |
| Зависимости | Предшественник, последователь, тип связи, задержка в днях |
| ИСР | Названия, номера, родительские узлы и число задач; отдельного поля описания у узла нет |
| Вехи | Название, описание, срок, статус и связь с ИСР, включая достигнутые вехи |
| Стикеры | Текст, автор, время и связи с задачами |
| Документы | Название, slug, текст и связи с задачами |
| История задач | Последние события, даты, прежние и новые значения |
| Риски | `RISK-id`, название, описание, статус, вероятность, влияние, уровень, ответственный, стратегия, оба плана, дата контроля, источник и связанная задача |

Бинарное содержимое вложений не читается этим сценарием. Если файл импортирован
в Markdown-документ, его текст передаётся через документы. Prompt запрещает
приписывать файлам содержание по имени. Цвета, координаты холста, поисковые векторы,
задания индексации, токены и прежние AI-отчёты не являются источниками оценки работ.

## Полнота и бюджет

Сначала передаются все текущие записи с ограничением длины текстовых фрагментов.
Прежние жёсткие ограничения на первые 25 описаний задач и на 6/20 рисков сняты.
История ограничена последними 50 событиями проекта или 20 событиями каждого проекта
портфеля; её полное число отдельно считается в базе.

JSON-контекст ограничен 90 000 символами. При переполнении сборщик последовательно
сокращает списки и тексты каждого проекта, сохраняя представительство видов источников.
Комментарии, назначения, файлы и чек-листы выбираются независимо от карточек задач, поэтому
сведения закрытой задачи могут попасть в анализ даже при сокращении списка задач.
Просроченные, срочные и активные задачи имеют приоритет; риски сортируются по статусу,
уровню и дате контроля. Документы и стикеры со связями имеют приоритет.

`context.entity_counts` и `projects[].entity_counts` содержат полное и переданное
число записей каждого вида. `context.omitted` перечисляет сокращения списков и текстов.
Эти границы получает модель, они же сохраняются в отчёте и показываются в интерфейсе.
Агрегированные показатели задач и рисков всегда относятся ко всем записям, независимо
от сокращений. Слишком большой даже после минимального сокращения контекст приводит
к ошибке до обращения к LLM, а не к молчаливому исключению проектов.

Проект без задач можно анализировать по описанию, срокам, документам, ИСР, вехам,
стикерам или рискам. Выводы по таким источникам не требуют выдуманных ссылок на задачи.

## Архитектура и проверка

`AnalyticsService` получает обязательные репозитории через `AnalyticsDbScope`;
композиция находится в `dependencies/scopes.py`. SQL остаётся в репозиториях,
связи читаются пакетно. Сессия чтения закрывается до обращения к LLM; результат
сохраняется в новой короткой области. Сбой любого источника прерывает анализ.

Проверки охватывают оба режима, все источники и описания, отсутствие секретов в
контексте, проекты без задач, большие объёмы, полный учёт сокращений и реальный
PostgreSQL со связями, доступными после закрытия сессии. Сохранённые старые отчёты
совместимы с новым необязательным полем `entity_counts`; для использования новых
источников нужно заново запустить анализ.

Для чек-листов отдельно учитываются `checklists` и `checklist_items`: полное и
переданное число чек-листов и пунктов. Сокращение текстов отмечается в `omitted`.
Незавершённый пункт сам по себе не означает просрочку или блокировку, а все отметки
не заменяют стадию завершения задачи. Аналитика рассматривает отметки как данные
пользователя и сопоставляет их с описанием, сроками и состоянием задачи.
