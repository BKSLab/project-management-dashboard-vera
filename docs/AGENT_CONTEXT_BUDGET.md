# Объём контекста проектного агента

Изменения от 22.09.2026. Цель — сократить повторную передачу данных между раундами, сохранив поиск по оригиналам и возможность дочитать нужный источник. Модель и число разрешённых раундов не менялись.

## Отбор и чтение

Стартовый поиск возвращает до пяти источников. В карточке поиска остаются ID, название, необходимые текущие свойства и краткое описание. Команда и соседние объекты больше не загружаются автоматически. Статистика и календарные расчёты по-прежнему подготавливаются, если планировщик выбрал соответствующий запрос.

Для документов и извлечённых проектных файлов используется сохранённое описание до 800 символов. Пока его нет, доступен явно обозначенный фрагмент оригинала до 400 символов. Список описаний ограничивается релевантными результатами: все документы проекта в prompt не перечисляются.

Полные тексты сохраняются в PostgreSQL и индексируются прежним способом. Краткое описание не заменяет FTS и embeddings: редкое условие, которого нет в саммари, по-прежнему находится по оригиналу. `matched_locations` указывает смещение проверенного фрагмента. Текст кандидата из Qdrant сверяется с текущей версией; чужие, удалённые и устаревшие данные не используются.

- `list_sources`, `search_sources`, `related_sources` возвращают компактные записи и страницы, по умолчанию по 5 объектов.
- `read_source` возвращает оригинальный текст по страницам с `offset`, `total_chars`, `next_offset`.
- `get_document` теперь также принимает `offset` и `max_chars` и возвращает страницу `document.content_md`. По умолчанию 4000 символов, максимум 8000. Эти смещения относятся к `content_md`; смещения `read_source` — к тексту общего источника с его заголовками.
- Точные формулировки, числа и цитаты агенту предписано проверять чтением оригинала.

## Подготовка описаний

Таблица `knowledge_source_summaries` хранит описание, хэш версии текста и ссылки на проект и исходный документ/файл. Изменение связей или служебных дат не вызывает повторной генерации. При изменении содержимого старый хэш перестаёт совпадать: старое описание сразу исключается из ответов, новое готовится в фоновой очереди.

Короткий источник до 800 символов сохраняется без вызова LLM. Более длинный читается частями до `KNOWLEDGE_SUMMARY_CHUNK_CHARS` (16000): модель последовательно обновляет компактное описание. Части покрывают весь текст, включая заголовки и длинные строки. Обработка документа имеет разовую стоимость на версию; для очень большого файла требуется несколько обращений.

Внешние вызовы проходят без занятого соединения с PostgreSQL. Извлечённый текст сохраняется до генерации описаний. Каждое готовое описание фиксируется отдельно перед переходом к следующему документу. Ошибка описания не исключает оригинал из поискового индекса; очередь повторяет отсутствующие версии, а уже готовые переиспользует. Неподдерживаемые и нераспознанные файлы сохраняют прежнюю диагностику.

Миграция `a81f247e930b` создаёт кэш и ставит проекты с существующими документами/файлами в штатную очередь, если задания ещё нет. При удалении оригинала или проекта кэш удаляется внешними ключами. Для установки достаточно `alembic upgrade head` и перезапуска backend; Compose выполняет миграцию автоматически перед запуском приложения.

## Бюджет каждого раунда

`AgentContextBudget` применяется перед каждым обращением основного агента. Он учитывает системную инструкцию, вопрос, историю, результаты поиска и инструментов. JSON передаётся без лишних пробелов. Одинаковые чтения одной страницы заменяют прежнюю копию; после дочитывания объекта его стартовое описание исключается из контекста.

История ограничена одновременно количеством сообщений и объёмом. При сокращении длинной последней реплики сохраняются её начало и конец со ссылками на показанные карточки. Полная переписка остаётся в базе. Старые результаты действий передаются компактными квитанциями; параметры и полные результаты сохраняются для интерфейса. Факт успешного действия не превращается в ошибку чтения и не теряется при сокращении.

При превышении бюджета уменьшаются списки и текстовые страницы, затем сворачиваются прежние чтения. `omitted`, `truncated`, `context_compacted` явно сообщают о сокращении. Курсор страницы корректируется, чтобы продолжение не пропускало непрочитанный текст или объекты. Вопрос и правила доступа не обрезаются; схемы аргументов инструментов не повреждаются.

| Настройка | По умолчанию | Назначение |
|---|---:|---|
| `AGENT_CONTEXT_TOKENS` | 12000 | Бюджет одного обращения вместе с системной инструкцией |
| `AGENT_HISTORY_TOKENS` | 1200 | Бюджет недавних реплик; краткая память получает до половины этого объёма |
| `AGENT_RETRIEVAL_LIMIT` | 5 | Число стартовых источников |
| `KNOWLEDGE_SUMMARY_CHUNK_CHARS` | 16000 | Максимальная часть текста для фонового описания |

Токены локально **оцениваются** как UTF-8 байты / 3 с запасом на сообщения. Это не точный токенизатор Gemini и не гарантия максимального счёта провайдера. В `project_agent.ask.context_rounds` записываются размеры до и после ограничения. `llm.request` записывает реальные `prompt_tokens`, `completion_tokens`, `cached_tokens`, ID ответа провайдера, длительность и схему операции, когда API возвращает эти поля. Тексты документов и переписки в эти метрики не записываются.

Суммарная оценка входа уменьшилась на **71,8%**. Это проверка объёма на заданном сценарии, не замер стоимости или качества живой модели. Подготовка саммари в это сравнение не входит. Число нужных раундов в реальном диалоге может отличаться. Локальный результат: `backend/.pytest_cache/context-comparison.json`.

Работа со SQL-каталогом и построение индекса по-прежнему используют полный снимок проекта на стороне сервера. Ограничения выше относятся к передаче контекста LLM, а не к максимальному объёму данных, читаемых из PostgreSQL.
