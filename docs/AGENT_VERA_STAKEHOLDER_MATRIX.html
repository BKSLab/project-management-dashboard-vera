Матрица «Власть / Интерес»

3

Внутренние стейкхолдеры (команда проекта)

В отличие от внешних, команда не требует индивидуальной стратегии коммуникации — она и так синхронизируется через рабочий процесс проекта (ИСР, статус-встречи 8.1). Здесь фиксируется только степень влияния каждой роли на ход проекта.

Роль Роль в матрице Влияние
Проджект-менеджер
Барабанщиков К.С.		 Управлять активно Принимает решения по срокам, бюджету и рискам; единая точка связи с заказчиком
Backend-разработчик Управлять активно Определяет архитектуру и технологический стек — задаёт технические рамки всего проекта
Frontend-разработчик Информировать Реализует интерфейс по уже утверждённой спецификации
UX-исследователь Информировать Формирует входные данные для дизайна, решений не принимает
UX-дизайнер Информировать Переводит исследование в макеты, влияет на UX в рамках своей зоны
Контент-эксперт (юрист) Информировать Отвечает за достоверность базы знаний, не влияет на архитектуру/сроки
Тестировщик (QA) Информировать Выявляет дефекты, решения по исправлению принимают другие роли
Бизнес-аналитик (BA) Информировать Задаёт метрики оценки, не влияет на ход разработки напрямую
Маркетинг (MKT) Информировать Готовит продвижение, не влияет на продуктовую разработку
