# Доски: API и сохранение данных

Доска — отдельный холст со стикерами, фигурами, текстом и соединителями. У проекта может быть несколько досок; личная доска хранится без проекта (`project_id = null`) и доступна только создавшему её локальному пользователю.

Проектные доски используют действующие правила участия в проектах. Члены проекта могут читать и изменять доску. Права API-ключа дополнительно ограничивают действия владельца; права ключа не открывают чужие проекты и личные доски. Регистрация и парольный вход сохраняются.

## Данные

`project_boards` хранит название, порядок вкладки, владельца, `revision`, `archived_at` и `editor_metadata`. Мягко удалённые доски не выдаются. Последнюю доску проекта удалить нельзя; последнюю личную доску удалить можно.

Стикеры сохраняют авторство и снимки имени/логина автора, координаты, размеры и связи с задачами. Связи допустимы только с задачами того же проекта. У личной доски связей с задачами нет. `board_id` определяет холст, `z_index` — общий слой со всеми фигурами доски.

Цвет стикера хранится в виде `#rrggbb`. Старые имена палитры принимаются как совместимый вход и преобразуются в цвета личного проекта:

| Имя | Цвет |
| --- | --- |
| `neutral` | `#f3efe4` |
| `yellow` | `#fff19a` |
| `blue` | `#c9edff` |
| `green` | `#d8f5b5` |
| `red` | `#ffbbb5` |
| `violet` | `#e4d2ff` |

Фигура имеет тип `rect`, `ellipse`, `diamond`, `text`, `arrow` или `line`. Для обычной фигуры задаётся рамка `x/y/w/h`; для линии и стрелки — `points`, а рамку вычисляет сервер. Концы соединителя могут ссылаться на фигуру или стикер той же доски через `{type, id, anchor}`. Удаление объекта отцепляет соединители и сохраняет их точки.

Metadata содержит `version: 1`, явные `groups`, список `locked` и автономные `templates`. Группа и шаблон имеют стабильный строковый ID. Блокировка защищает от случайной правки, но не заменяет проверку доступа.

## Маршруты

Все пути начинаются с `/api/v1`.

| Метод | Проектная доска | Личная доска |
| --- | --- | --- |
| GET / POST списка | `/projects/{pid}/boards` | `/boards` |
| PATCH / DELETE доски | `/projects/{pid}/boards/{bid}` | `/boards/{bid}` |
| GET сцены | `/projects/{pid}/boards/{bid}/content` | `/boards/{bid}/content` |
| POST смешанного пакета | `/projects/{pid}/boards/{bid}/batch` | `/boards/{bid}/batch` |
| GET / PUT metadata | `/projects/{pid}/boards/{bid}/editor-metadata` | `/boards/{bid}/editor-metadata` |

Переименование и изменение порядка передают актуальную `revision`. Удаление передаёт её в query-параметре. Создание передаёт `title`. Сцена возвращается как `{board, stickers, shapes}`.

Под путём отдельной доски доступны `/stickers`, `/stickers/{id}`, `/stickers/{id}/position`, `/shapes`, `/shapes/{id}` и `/shapes/{id}/to-sticker`. Исходные пути `/projects/{pid}/board/stickers` сохранены для совместимости: чтение и создание используют первую доску, изменение находит стикер на активной доске проекта.

`POST /boards/{bid}/create-project` принимает `{expected_revision, project}`. Проект создаётся с локальным владельцем и участниками; доска переходит в него с прежним ID, объектами, привязками и metadata. Создание проекта и перенос доски выполняются одной транзакцией.

## Пакет и конфликты

`/batch` принимает до 500 операций над фигурами и стикерами. Поддерживаются создание, изменение, перемещение и удаление. Новые объекты получают `client_id`; соединители и metadata могут ссылаться на них в том же пакете. Например:

```json
{
  "ops": [
    {"op": "create_sticker", "client_id": "note", "data": {"body": "Начало", "color": "yellow", "canvas_x": 40, "canvas_y": 40}},
    {"op": "create_shape", "client_id": "step", "data": {"kind": "rect", "x": 400, "y": 80, "w": 180, "h": 100, "label": "Шаг"}},
    {"op": "create_shape", "client_id": "edge", "data": {"kind": "arrow", "points": [[270, 155], [400, 130]], "start_ref": {"type": "sticker", "client_id": "note", "anchor": "right"}, "end_ref": {"type": "shape", "client_id": "step", "anchor": "left"}}}
  ],
  "editor_state": {
    "expected_revision": 1,
    "metadata": {"version": 1, "groups": [], "locked": [], "templates": []}
  }
}
```

Сервер блокирует доску и затронутые строки, проверяет ревизии, принадлежность ссылок и блокировки до фиксации. Ошибка откатывает весь пакет, включая созданные объекты, привязки и metadata. Ответ содержит `id_map`, изменённые объекты, удалённые ID и `editor_state` с новой ревизией.

Любая запись сцены через сервисы изменяет общую ревизию доски. Ревизия содержимого стикера и его перемещение разделены: перемещение всё равно делает прежнюю общую ревизию доски устаревшей. При несовпадении версии сервер возвращает 409. У batch нет `request_id` и отдельной гарантии повторной выдачи потерянного ответа: клиент должен согласовать свежую сцену перед повтором.

Шаблон сохраняет самостоятельное выделение, внутренние соединители, группы и блокировки; связи с задачами в шаблон не входят. Вставка шаблона и история смешанной сцены используют тот же атомарный batch.
